# #29.7.2.16 — Exact Mechanical Portfolio-Level Aggregation

## Status
LOCKED_AND_IMPLEMENTABLE. Read-only aggregation over multiple strategy populations. "How did the combined collection of strategies perform as one capital allocation?"

## Ownership
Owns portfolio identity; strategy inclusion/exclusion; combined trade population; combined counts / gross-net P&L / gross-net R; win/loss/BE; win rate; expectancy; profit factor; cumulative; equity; drawdown; recovery; underwater; streaks; distributions; period statistics; strategy contribution; portfolio snapshots. Does NOT own setup/strategy qualification, entry/sizing/exit/costs, trade classification, individual accounting, strategy definitions/optimization, capital-allocation decisions.

## Canonical Definition
- **Identity:** `portfolio_id` immutable; `PortfolioDefinition { portfolio_id; included_strategy_ids; excluded_strategy_ids; creation_time; version }`. Membership never inferred from trade behavior.
- **Population:** finalized trades whose `strategy_id ∈ included`. Only finalized trades.
- **Inclusion explicit; exclusion wins** (`included={A,B,C}, excluded={C}` → `{A,B}`).
- **Contribute once:** each trade → exactly one strategy → ≤ one portfolio membership. `PortfolioTradeCount = Σ qualifying finalized trades`.
- Merged chronological sequence `closed_time ASC, trade_id ASC` (identical timestamps of different trades are distinct, not duplicates).
- Combined `GrossPnL / NetPnL / GrossR / NetR = Σ` over included trades (R consumed, never recomputed from aggregate P&L).
- Win rate (BE in denominator), averages, expectancy, profit factor inherit .3/.4.
- **Portfolio equity:** `PortfolioEquity_i = PortfolioStartingEquity + CumulativeNetPnL_i`; starting equity explicitly supplied → else `PORTFOLIO_STARTING_EQUITY_MISSING`.
- **Path-dependent stats (drawdown, recovery, underwater, streaks, equity, trade-sequence) computed from the MERGED chronological portfolio population** — never by summing/averaging strategy-level values (§47/§48 critical principle).
- **Strategy contribution:** retains `trade_id/strategy_id/closed_time/NetPnL/NetR/result`. `Σ StrategyContributionPnL = PortfolioNetPnL`; `Σ StrategyContributionR = PortfolioNetR`; `Σ StrategyTradeCount = PortfolioTradeCount`.
- **Versioning:** `portfolio_id + portfolio_version` fixes membership. v1 statistics never silently become v2. Strategy statistics remain independent of portfolio membership; portfolio never rewrites strategy results.
- Empty portfolio: additive totals 0; observation-dependent statistics `NULL`; starting equity still exists if supplied.
- Object: `PortfolioPerformance { portfolio_id; portfolio_version; included/excluded; population_start/end; timezone; starting_equity; counts; gross/net P&L/R; averages; win_rate; expectancy; profit_factor; cumulative; *_reference; strategy_contributions; source_trade_ids; calculation_timestamp; calculation_version }`.

## Duplicate Handling (C2-consistent)
`duplicate trade_id → DATA_INTEGRITY_ERROR → fail-closed → no finalized ambiguous portfolio snapshot`. Consistent with Amendment 001 C2 (no supersession needed).

## Capital Interaction
Does not redistribute capital between strategies or decide affordability — deferred to a future capital-allocation/risk-management layer (optional future extension).

## Hard Invariants
Trade/result/P&L/R/Gross conservation; strategy-contribution conservation; equity conservation; each `trade_id` contributes ≤ once; no look-ahead (`closed_time <= T`); historical immutability; strategy immutability; **no double aggregation** (portfolio expectancy/PF/drawdown recomputed from combined population, never combined from strategy statistics).
