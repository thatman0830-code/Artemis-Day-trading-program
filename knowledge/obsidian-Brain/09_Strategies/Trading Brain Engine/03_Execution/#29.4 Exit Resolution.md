# #29.4 — Exact Mechanical Gap-Through / Exit Resolution

## Status
LOCKED_AND_IMPLEMENTABLE

## Ownership
Resolves actual stop/target exits after the position is OPEN and protective orders ACTIVE. Does not select `StopPrice` (#13), construct protective orders (#29.3), or calculate P&L (#29.7.1).

## StopPrice vs ExitPrice
`StopPrice` = protective trigger established upstream. `ExitPrice` = mechanically resolved executable exit price. **`StopPrice != guaranteed ExitPrice`** — a stop is not a guaranteed-price order.

## Normal Stop
- Long: path reaches `S` without the first observable price already below `S` → `ExitReason = STOP_LOSS`, `ExitPrice = S`.
- Short: path reaches `S` without the first observable price already above `S` → `ExitReason = STOP_LOSS`, `ExitPrice = S`.

## Gap-Through Stop
- Long: `FirstObservablePrice < StopPrice` → `ExitReason = STOP_LOSS_GAP`, `ExitPrice = FirstObservablePrice`. Base OHLC: `Open < S ⇒ ExitPrice = Open`. (e.g. S=5014.00, Open=5008.00 → 5008.00; no fabricated 5014.00 fill.)
- Short: `FirstObservablePrice > StopPrice` → `ExitReason = STOP_LOSS_GAP`, `ExitPrice = FirstObservablePrice`. Base OHLC: `Open > S ⇒ ExitPrice = Open`.

## Data-Resolution Hierarchy
Tick/trade-level → sub-1M → 1M → higher-timeframe OHLC. Higher-resolution chronology overrides higher-timeframe OHLC assumptions. Base OHLC-only: `FirstObservablePrice = candle Open`. No future intrabar information may improve a prior historical execution.

## Target Gap
Targets are limit orders; a favorable gap beyond target does **not** improve the fill. Long: `next observable > T → ExitReason = TARGET, ExitPrice = T`. Short: `next observable < T → TARGET, ExitPrice = T`. Preserve the stop/target asymmetry (stop gap = adverse first observable; target gap = fixed TargetPrice).

## OHLC Ambiguity & Precedence
If both SL and TP are reachable inside the same OHLC candle with no finer chronology → `ExitReason = OHLC_AMBIGUOUS_STOP_PRIORITY` (stop wins). **Gap-stop logic has higher precedence:** if the candle opens beyond `StopPrice` → `STOP_LOSS_GAP` (not ambiguity), because the first observable price already proves the stop event preceded any later high/low path.

## Exact Resolution Order
1. Require `PositionState = OPEN`. 2. Require protective orders ACTIVE. 3. Determine highest-resolution valid chronology. 4. Inspect first observable post-entry executable price. 5. If beyond StopPrice → resolve `STOP_LOSS_GAP` immediately, `ExitPrice = FirstObservablePrice`, cancel target OCO sibling, close, stop processing. 6. Else evaluate chronological SL/TP events. 7. If chronology establishes one first → resolve it. 8. If both reachable in one unresolved OHLC interval and chronology cannot order → `OHLC_AMBIGUOUS_STOP_PRIORITY` (stop wins). 9. Cancel remaining OCO order. 10. `OPEN → CLOSED` exactly once.

## Execution-Cost Boundary
Adverse gap is represented through actual `ExitPrice` (economic effect → GrossPnL), **not** an additional explicit cash cost. See [[#29.5 Execution Costs]]. No double-count.

## Hard Invariants
Normal stop `ExitPrice = StopPrice`. Long/short gap `ExitPrice = FirstObservablePrice`. Gap-stop precedence over unresolved same-candle SL/TP ambiguity. Target gap `ExitPrice = TargetPrice`. Higher-resolution chronology overrides OHLC assumptions. #29.4 may not modify StopPrice, alter #13 history, invent a better fill, or double-count gap impact as a cash cost. One position receives exactly one terminal exit.
