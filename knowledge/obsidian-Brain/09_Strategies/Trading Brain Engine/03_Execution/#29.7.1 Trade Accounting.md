# #29.7.1 — Exact Mechanical Individual Trade Accounting

## Status
LOCKED_AND_IMPLEMENTABLE

## Ownership
Owns per-trade P&L, R, and equity accounting. Source of truth for `TradeResult` (WIN/LOSS/BREAKEVEN). Consumes economic prices + cash costs from [[#29.5 Execution Costs]] and finalized lifecycle fields from [[#29.6 Position Lifecycle]]. Does not modify upstream entry/exit/quantity/stop/target/costs/lifecycle.

## Canonical Definition (locked formulas)
```
GrossPnL = (EconomicExitPrice − EconomicEntryPrice) × DirectionMultiplier × Quantity × ContractMultiplier
NetPnL   = GrossPnL − ExplicitCashCosts
GrossR   = GrossPnL / ActualRiskDollars
NetR     = NetPnL  / ActualRiskDollars
PostTradeEquity = PreTradeEquity + NetPnL
```
- `ActualRiskDollars` comes from [[#29.2 Position Sizing]] and must be positive; non-positive risk → `ACCOUNTING_ERROR` (never ∞ / NaN / zero R).
- Classification by `NetPnL`: positive → WIN, negative → LOSS, exact zero → BREAKEVEN.
- Precision: decimal, ≥28 significant digits, ROUND HALF UP, exact-zero breakeven.

## Object
`TradeAccounting { trade_id; setup_id; strategy_id; direction; opened_time; closed_time; gross_pnl; net_pnl; gross_r; net_r; pre_trade_equity; post_trade_equity; trade_result; ...finalized fields }`.

## Hard Invariants
- accounting never changes upstream entry/exit/quantity/stop/target/lifecycle/costs
- `ActualRiskDollars > 0`; classification from `NetPnL` (exact zero → BREAKEVEN)
- deterministic decimal precision ([[Precision — Rounding Policy]])
