# #29.1 — Exact Mechanical Entry Order Model

## Status
LOCKED_AND_IMPLEMENTABLE

## Ownership
Owns entry order construction and fill determination from the frozen entry zone/EQ after [[#29.0 Execution Eligibility]] authorizes a Trade. Does not decide setup validity/eligibility, select the zone/EQ (#28), size (#29.2), select the stop (#13), or resolve exits (#29.4).

## Canonical Definition
- #28 fixes the zone / EQ.
- #29.0 must provide a current `TRADE_AUTHORIZED` record before an order is created.
- **Bullish** uses a **buy limit** at exact EQ; **bearish** uses a **sell limit** at exact EQ.
- **OHLC touch rules** determine fills; **no touch = no fill**.
- Invalidation cancels the order.
- **No look-ahead / same-candle OHLC ambiguity** handling.
- **One-live-position** constraint (see [[#29.6 Position Lifecycle]]).

## State / Lifecycle
Entry order: `PENDING → ACTIVE → PARTIALLY_FILLED | FILLED | CANCELLED | REJECTED | EXPIRED`. Partial fills are immutable [[Execution Entity Hierarchy|Fill]] records and create exposure equal only to filled quantity. A Position exists only after the first confirmed entry Fill (see #29.6). `EntryZone touched ≠ Position exists`; `EntryOrder created/triggered ≠ Position exists`; `Entry fill → Position exists`.

## Hard Invariants
- limit placed at frozen EQ; no improvement beyond EQ
- no touch → no fill; invalidation cancels
- no look-ahead; one live position at a time
- every Order links to one Trade; every Fill links to its Order and Trade
- rejected/canceled/expired quantity is never treated as filled quantity
- if #29.0 revokes eligibility while unfilled, cancel; after any partial fill, preserve exposure and hand it to #29.6
